# 开奖数据工作台

## 运行

```bash
uv venv
uv pip install -r requirements.txt
uv run python main.py
```

点击首页底部“登录管理”，可直接配置网站账号密码及 ttshitu 打码平台账号密码，也可继续用“导入登录态”粘贴目标网站 Local Storage 的 `user` JSON。“打开打码网站”会在默认浏览器进入 ttshitu 用户中心。账号配置保存后默认开启自动续登；“立即登录”可主动获取图片验证码、调用打码平台并向当前网页地址对应的 API 提交登录。

登录态保存于当前用户目录 `.lottery-sheet-workflow/auth.json`，自动续登账号配置保存于 `login_credentials.json`；两者权限均限制为仅当前用户可读写。保存后的密码始终保留在输入框中，默认以圆点遮挡，可点击右侧眼睛切换明文/密文；日志和错误信息不会输出完整密码或 token。验证码识别使用 ttshitu `typeid=1` 的四位纯数字协议。

点击首页“开始”后，程序先调用网站接口检查登录状态。若已失效，会显示 5 秒红色提示、自动识别验证码并重新登录；成功后显示绿色提示并继续任务。轮询、历史补录、盈亏查询或投注接口在运行中明确返回登录失效时，也会重新登录并只重试失败的当前步骤。投注 POST 仅在服务端明确返回登录失效时原样重试，网络超时仍不重试，避免重复下单。

## 开奖配置：玩法和 Excel

1. 首页“历史补录”先选玩法，再使用唯一的“选择 Excel”按钮。玩法二还需选择逻辑一或逻辑二；每个选项右侧的 `?` 可查看规则。
2. 默认勾选“使用副本（保留源 Excel）”：在原文件同目录创建 `原文件名_已完成.xlsx`，补录只写副本。
3. 取消勾选：直接补录当前选中的源 Excel。玩法一只填写 B 列特码空白；玩法二把平码 1–6 和特码写入 B:H 的空白格。已有值和公式不覆盖。
4. 文件选好后也可切换模式；已建立的源文件/副本对应关系会保存，切回副本时继续使用原副本。两份文件不会互相合并。
5. 同名副本已存在且不是当前已绑定的副本时，程序不会覆盖。若要续用该文件，取消勾选，再通过同一个按钮选择已有副本。
6. “表格信息与模板”可按当前玩法下载对应模板。玩法一显示 H1/I1；玩法二显示 B:H 补录列及当前逻辑。所选玩法和 Excel 模板不一致时禁止启动，避免写错列。
7. 点击“开始”立即查询并补录一次，随后按“运行配置”的轮询间隔持续自动补录；点击“停止”结束轮询。
8. 补录或轮询期间，文件选择、写入方式、登录态及地址修改锁定。停止后可更改。登录管理弹窗关闭不影响轮询；退出主窗口会停止任务并等待当前请求或写入结束。

运行前请关闭正在编辑的 Excel 文件。设置与写入路径会保留到下次启动。

首页默认大小为 800 × 720；开奖配置不再弹窗。底部“登录管理”集中提供登录态导入、获取指引、清除及网页地址配置。

## 自动投注与玩法规则

在“投注参数”保存延后期数、连续期数、每期每注积分并开启“是否自动投注”后，程序按首页所选玩法检查预警并启动或重启一轮投注：

- **玩法一**：A 列匹配期号，B 列补特码；D 列预警按现有规则触发，排除 H1 尾数和 I1 生肖。
- **玩法二 / 逻辑一**：B:G 补六个平码、H 补特码；程序从原始开奖数据复算 J 列预警及 O/P 尾数和生肖，选号规则与玩法一相同。
- **玩法二 / 逻辑二**：程序复算 K 列预警；命中后读取触发行当前 R 列预测生肖，排除该生肖的号码，其余 1–49 号码全部投注。

Excel 的公式缓存可能在程序保存后失效，因此 J/K、O/P/R 的运行判断均由 Python 按模板公式复算，不依赖缓存结果。规则通过 `bet_rules.py` 注册表接入，后续新增玩法可增加适配器而不改 HTTP 投注客户端。

公共投注流程：

1. 补录新期开奖结果，并按 Excel 公式同等逻辑判断最新一期 D 是否归零；
   每天导入已清空的新表时会先执行历史补录，再读取 H1/I1。首期尚未开奖或网页还没有与表格期号匹配的数据时只等待下一轮，不把空表当成运行错误；
2. “延后期数”表示跳过多少期：填 0 从下一期开始，填 1 跳过下一期后开始，填 2 跳过后两期后开始；
3. 投注进行中如果再次出现 D=0，旧轮次尚未执行的计划立即作废，并以新的零值重新延后、重新连投。例如 119=0、延后1期、连投3期会投注121–123；若123再次为0，则重新投注125–127；
4. 连续投注期数与积分输入联动：连投3期会显示3个积分框，可分别设置如1、2、5；三个投注期中，每个所选号码分别使用1、2、5积分。新 D=0 重启后从第1期积分重新开始；
5. 每期重新读取并计算当前玩法的排除尾数/生肖；
6. 获取宾果六合当前期号、实时赔率和动态 `game_id`；
7. 所有玩法都只构造特码 B 注单（`specialCodeB / guessNumberB`），不会切换到特码 A；
8. 每个期号最多尝试一次，去重记录不会因新 D=0、规则变化或轮次重启而清空。若投注接口已经进入下一期、但开奖历史尚未返回紧邻的上一期开奖结果，本轮会等待历史和 Excel 追平后再按最新规则下注，避免旧轮次抢先投注并与新轮次重叠。即使某期因积分不足被拒绝，该期仍属于当前轮次的连续期数，不会向后多投一期；错误写入“查看日志”。成功投注也会记录期号、全部号码及其对应积分、合计积分和投注进度。

投注状态保存在 `.lottery-sheet-workflow/bet_state.json`。重新保存投注参数会开始一轮新的次数计数。

运行日志按中国时区显示到秒，并持久保存于 `.lottery-sheet-workflow/runtime.log`；软件重启后会重新载入最近 2000 行。单个日志达到 5 MB 时轮转为 `runtime.log.1`。“清除日志”会在确认后同时删除当前日志和轮转备份。

## 告警、缺失开奖与盈亏停投

- 网络离线、接口异常、自动续登失败、投注失败和盈亏查询失败会写入日志、播放明显提示音，并通过系统托盘显示具体原因；Windows 下显示在右下角通知区域。登录失效且自动续登成功时只显示红/绿 Toast 并记录恢复步骤，不停止任务。
- 网页没有某一期开奖结果时，对应开奖列保持空白；玩法一模板的 D 列公式会继续在上一期基础上加 1。程序同步时只升级可识别的玩法一旧版公式，不改写玩法二或自定义公式。
- 首页显示“今日盈亏”和“刷新盈亏”按钮，数值与网页“今日结果”使用同一数据源：`GET /api/v1/member/issueData/{game_id}` 的 `data.next.totalWin`，不再读取可能与网页不同步的 `getUserInfo.totalWin`。
- “运行配置”分别设置“查询与下注轮询时间间隔”和“查询盈亏值时间间隔”。盈亏定时查询独立运行，不要求发生投注，也不依赖历史开奖轮询；手动按钮仍可随时刷新。
- “投注参数”可分别设置盈利停止值和亏损停止值（均可留空，亏损值填正数）。自动检查达到阈值后，在提交任何投注前立即停止当天自动投注并报警；停止状态锁定到中国时区当天结束。盈亏查询遇到网络连接失败或超时时会间隔 1 秒重试 5 次；仍然失败时采用安全停止策略：本轮不投注，并记录原因和告警。登录失效会先自动续登并恢复当前接口；其他业务错误或响应格式异常不会重试。

## 开发调试按钮

直接从源码运行 `main.py` 会自动视为开发模式并显示调试入口：

```bash
cd code && uv run python main.py --dev
```

`uv run python main.py` 会自动显示。窗口右下方会出现红色悬浮“调试”按钮，可以分别测试提示音（连续播放三遍）、系统通知、全部告警或停止警报。macOS 使用通知中心，Windows 使用右下角系统通知。打包后的正式程序不会创建该按钮；源码调试时如需强制隐藏，可在运行前设置环境变量 `LOTTERY_DEV_MODE=0`。
